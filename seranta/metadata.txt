about=Seranta (from "serat", fibre, and "Nusantara") turns the manual steps of preparing and reviewing an FTTH (GPON) access-network design into a repeatable, documented process inside QGIS. It is built for designers who survey homepasses and poles in the field and design the network with automatic design software.
  <br/><br/><b>Tool 1 – Prepare design input + survey QC (before design)</b>: homepass spreadsheet (XLSX/CSV) to a homepass layer with automatic IDs; cluster KMZ to a pole KMZ and a road layer snapped and split at poles; nine review standards (homepass-to-pole distance, other service boundaries, administrative area, spreadsheet vs KMZ and duplicates, service boundary, design status, FDT colocation, community-permit document, pole spans); engineering-based pole rules (span, mid-span clearance, bends); efficiency hints.
  <br/><br/><b>Tool 2 – Post-design</b>: FDT-FAT code table from the design export and splice plan; colour-coded (TIA-598) fibre/tube table for every closure; post-design checks.
  <br/><br/><b>Tool 3 – FDT &amp; FAT allocation estimate</b>: FATs grouped along the cable route, nearest existing FDT with spare capacity, new FDT proposals, worst-case link budget.
  <br/><br/><b>Tool 4 – Design package QC</b>: served status, FAT coverage, cable ends, FDT/FAT hierarchy and capacity, FDT in Feeder and Distribution packages, BOM reconciliation, FAT-homepass distance, codes, devices on poles, spans, idle poles, slack, KMZ conventions, plus seven package rules (FDT codes, premises and splitters, properties vs code table, existing poles vs a reference pole layer, pancingan and closure ratios, devices and pancingan on poles). Every rule reports PASS, ERROR, WARNING, INFO or UNVERIFIED; missing data is never counted as a pass.
  <br/><br/><b>Reports people understand</b>: every HTML report opens with one plain sentence on what to do, and every rule explains what was checked, why it matters and what to do; every finding is written in plain language with a map link, and the technical detail sits underneath. Fonts are embedded (works offline, prints to PDF).
  <br/><br/><b>Your own standards</b>: thresholds live in JSON profiles with the source and approval status of every number. Organisation profiles can be kept outside the plugin (QGIS profile folder seranta/profiles, setting seranta/profile_dir or the SERANTA_PROFILE_DIR environment variable) so plugin updates never overwrite them.
  <br/><br/><b>Requirements</b>: QGIS 3.22 LTR up to 4.x (Qt5/Qt6), Windows, Linux or macOS. No extra Python packages, no internet connection and no user account needed. The automatic design software is a separate product and is not included. User interface and reports are in Indonesian.
