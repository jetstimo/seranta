about=Seranta (from "serat", fibre, and "Nusantara") turns the manual steps of preparing and reviewing an FTTH (GPON) access-network design into a repeatable, documented process inside QGIS. It is built for designers who survey homepasses and poles in the field and design the network with automatic design software.
  Tool 1 – Prepare design input + survey QC (before design): homepass spreadsheet (XLSX/CSV) to a homepass layer with automatic IDs; cluster KMZ to a pole KMZ and a road layer snapped and split at poles; nine review standards (homepass-to-pole distance, other service boundaries, administrative area, spreadsheet vs KMZ and duplicates, service boundary, design status, FDT colocation, community-permit document, pole spans); engineering-based pole rules (span, mid-span clearance, bends); efficiency hints.
  Tool 2 – Post-design: FDT-FAT code table from the design export and splice plan; colour-coded (TIA-598) fibre/tube table for every closure; post-design checks.
  Tool 3 – FDT & FAT allocation estimate: FATs grouped along the cable route, nearest existing FDT with spare capacity, new FDT proposals, worst-case link budget.
  Tool 4 – Design package QC: served status, FAT coverage, cable ends, FDT/FAT hierarchy and capacity, FDT in Feeder and Distribution packages, BOM reconciliation, FAT-homepass distance, codes, devices on poles, spans, idle poles, slack, KMZ conventions, plus seven package rules (FDT codes, premises and splitters, properties vs code table, existing poles vs a reference pole layer, pancingan and closure ratios, devices and pancingan on poles). Every rule reports PASS, ERROR, WARNING, INFO or UNVERIFIED; missing data is never counted as a pass.
  Reports people understand: every HTML report opens with one plain sentence on what to do, and every rule explains what was checked, why it matters and what to do; every finding is written in plain language with a map link, and the technical detail sits underneath. Fonts are embedded (works offline, prints to PDF).
  Your own standards: thresholds live in JSON profiles with the source and approval status of every number. Organisation profiles can be kept outside the plugin (QGIS profile folder seranta/profiles, setting seranta/profile_dir or the SERANTA_PROFILE_DIR environment variable) so plugin updates never overwrite them.
  Requirements: QGIS 3.22 LTR up to 4.x (Qt5/Qt6), Windows, Linux or macOS. No extra Python packages, no internet connection and no user account needed. The automatic design software is a separate product and is not included. User interface and reports are in Indonesian.

changelog=3.5.2 Interactive reports and Word output. Every finding now has a stable ID (F-0001 in tool 1, finding ID in tool 4) shared by the HTML report, the Word report, the finding layers and the QC Navigator; a map picture is drawn for every finding (highlighted geometry, pole/device labels, scale bar, north arrow; no basemap or internet needed) and saved in QC_GAMBAR; a Word report (.docx) with a summary table and one section per finding (meaning, action, value vs limit, location, rule source, reviewer note, map picture) is written next to the HTML. HTML reports: enterprise-style neutral design (Inter, accessible WCAG AA colours, dark mode), KPI tiles, deep links (#F-0001), keyboard shortcuts (j/k/x/g/o/?), per-finding "checked" status saved in the browser with a review CSV, enlargeable map pictures, Word download button. QC Navigator: "Copy picture" (paste straight into Word) and "Word report" for the findings currently shown, rendered from the live QGIS map. Mid-span cable height: pole embedment 1/6 of pole length (national distribution construction standard), design sag 1.5 percent, review band 4.7-5 m (NESC 232-1) summarised, notes only below 4.7 m; span and cable-height labels no longer run together (span above the line, height below, dashed); re-running tool 1 in the same QGIS session no longer fails to overwrite the finding layer. 55 automated tests.
  3.5.1 Evidence-based tolerances (pass / review / fail). Tool 1: homepasses only a few metres outside the hand-drawn cluster BOUNDARY are reported as INFO "at the edge" within a GPS tolerance (default 10 m, GPS.gov 4.9 m open sky; PLOS ONE 2019 7-13 m urban) instead of a mandatory fix, and every boundary/Funnel/pole-distance finding now records its distance and limit; Design Lite double-tagging adds review bands (HP 2-5 m, new pole 1.5-10 m); unused survey poles are WARNING. Tool 3: link-budget verdict uses design losses (1:4 7.25, 1:8 10.38, connector 0.25 dB) with a 3 dB margin; worst-case maxima are reported as "thin budget" instead of failing twice. Tool 4: slack spacing is checked on new cables only (existing/colo cables ignored); a cable tail after the last FAT within the loop limit (100 m / 2 spans) is WARNING, and spans are counted as spans, not poles. Tool 2: floating-FAT tolerance taken from the profile. QC-01 grouping no longer treats the design FDT itself (already listed in the latest existing-network file or in the code register) as a group used elsewhere. New profile parameters with sources; 54 automated tests.
  3.5.0 Reviewer worklist and audit completeness for tool 4: QC_APD_TEMUAN.xlsx (summary, findings with plain-language meaning and action, evidence and source file, map link, review status drop-down read back on the next run, input completeness, FDT grouping); input completeness table in the HTML report (which inputs were used, how many objects, which rules cannot run without them); evidence, source file, network scope and location filled for every finding (table findings such as splice-plan mismatches now point to the device on the map); FDT grouping candidates in QC-01 (area group of nearby existing FDTs, nearest existing FDT, next free code; new area groups reported as INFO, a group already used elsewhere as WARNING); QC Navigator filters by rule and by network scope (Feeder/Distribution), tooltips with evidence; rules with missing data stay UNVERIFIED even when they only add INFO notes. 47 automated tests.
