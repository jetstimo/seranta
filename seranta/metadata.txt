about=Seranta (from "serat", fibre, and "Nusantara") turns the manual steps of preparing and reviewing an FTTH (GPON) access-network design into a repeatable, documented process inside QGIS. It is built for designers who survey homepasses and poles in the field and design the network with automatic design software.
  Tool 1 – Prepare design input + survey QC (before design): homepass spreadsheet (XLSX/CSV) to a homepass layer with automatic IDs; cluster KMZ to a pole KMZ and a road layer snapped and split at poles; nine review standards (homepass-to-pole distance, other service boundaries, administrative area, spreadsheet vs KMZ and duplicates, service boundary, design status, FDT colocation, community-permit document, pole spans); engineering-based pole rules (span, mid-span clearance, bends); efficiency hints.
  Tool 2 – FDT & FAT allocation estimate: FATs grouped along the cable route, nearest existing FDT with spare capacity, new FDT proposals, worst-case link budget.
  Tool 3 – Post-design: FDT-FAT code table from the design export and splice plan; colour-coded (TIA-598) fibre/tube table for every closure; post-design checks.
  Tool 4 – Design package QC: served status, FAT coverage, cable ends, FDT/FAT hierarchy and capacity, FDT in Feeder and Distribution packages, BOM reconciliation, FAT-homepass distance, codes, devices on poles, spans, idle poles, slack, KMZ conventions, plus seven package rules (FDT codes, premises and splitters, properties vs code table, existing poles vs a reference pole layer, pancingan and closure ratios, devices and pancingan on poles). Every rule reports PASS, ERROR, WARNING, INFO or UNVERIFIED; missing data is never counted as a pass.
  Reports people understand: every HTML report opens with one plain sentence on what to do, and every rule explains what was checked, why it matters and what to do; every finding is written in plain language with a map link, and the technical detail sits underneath. Fonts are embedded (works offline, prints to PDF).
  Your own standards: thresholds live in JSON profiles with the source and approval status of every number. Organisation profiles can be kept outside the plugin (QGIS profile folder seranta/profiles, setting seranta/profile_dir or the SERANTA_PROFILE_DIR environment variable) so plugin updates never overwrite them.
  Requirements: QGIS 3.22 LTR up to 4.x (Qt5/Qt6), Windows, Linux or macOS. No extra Python packages, no internet connection and no user account needed. The automatic design software is a separate product and is not included. User interface and reports are in Indonesian.

changelog=3.5.7 Evidence inside the report, so reviewers never need to open the source folder. Every finding in the HTML reports has a tabbed evidence panel: Picture (static capture with copy-to-clipboard and PNG download), Rule vs value (requirement, measured value, difference and percentage), Source data (verbatim rows from the homepass spreadsheet with the deciding columns highlighted, pole/FAT/FDT/homepass/cable attributes from the KMZ or design export, with file names) and Trail (finding ID, rule code, rule basis, source file, profile and rule version, plugin version, run time). The interactive map can copy or download a picture of the current view with title, centre coordinates, scale bar and north arrow. A duplicate homepass whose second row has no KMZ point is reported once (one root cause, one finding). Design tokens refined after a review of large telecom design systems (brand-neutral petrol-teal accent, functional status colours separate from the accent, distinct status icon shapes for colour-blind users, IBM Plex Mono for data excerpts). 62 automated tests.
    3.5.6 Interactive findings map in every HTML report (tool 1 and tool 4), embedded and working offline (Leaflet 1.9.4, BSD-2): every network object (homepass with its spreadsheet attributes, poles with height, FAT/FDT with premises and splitters, closures, cables with core count and KMZ folder, boundaries) and every finding on one map. Clicking a finding shows its explanation, action, value vs limit, line length, picture, review tick (synced with the list), coordinates in decimal and DMS, nearby objects and nearby findings; clicking an object shows all its attributes and the findings attached to it. Optional satellite or street basemap when online (provider attribution shown), links to satellite maps, 3D earth view and street-level view, severity filters, layer toggles, search, distance measuring, full screen and keyboard navigation. Refreshed report design (navy-teal header, embedded Poppins and Inter, rounded KPI tiles, automatic dark mode).
    3.5.5 Menu numbers now follow the working order: 1 prepare input + survey QC, 2 FDT & FAT allocation (before design), 3 post-design code tables, 4 design package QC. Processing algorithm IDs are unchanged, so existing scripts and models keep working. The built-in handbook is now interactive: a clickable workflow map with saved checklists, a step guide, a searchable dictionary of every finding code, a short quiz, handbook search, light/dark theme and print to PDF.
    3.5.4 Fixes from a second review on real projects: the scanner-app badge embedded on every page of a community-permit PDF is no longer reported as a digitally pasted stamp or signature; a pole span drawn twice by two overlapping route lines is evaluated once, so span and low-cable findings are no longer duplicated. 61 automated tests.
    3.5.3 More precise and clearer QC results, verified against real projects. Tool 1: a home whose HPDB house number equals the KMZ point name but whose coordinates differ by more than the tolerance (up to 30 m, smartphone GNSS error in settlements) is reported once as HP_BERGESER (review) instead of twice as missing; KMZ points in a DUPLICATE/ERROR folder are counted only as duplicates; a coverage note is added when the KMZ holds far more homes than the HPDB and when HPDB cluster names are mixed. Tool 4: lines in the "Keterangan Infra" annotation folders are no longer treated as cables (slack, bill of quantities, pancingan ratio); pancingan is not flagged for a missing COLO/NEW INFRA label; device-on-pole check shows "not verifiable" instead of pass when some devices cannot be checked; rules that pass with a coverage limit say "pass with note" in HTML and Word; the rule version shown is the version of the code that evaluated it. 59 automated tests.
    3.5.2 Interactive reports and Word output. Every finding now has a stable ID (F-0001 in tool 1, finding ID in tool 4) shared by the HTML report, the Word report, the finding layers and the QC Navigator; a map picture is drawn for every finding (highlighted geometry, pole/device labels, scale bar, north arrow; no basemap or internet needed) and saved in QC_GAMBAR; a Word report (.docx) with a summary table and one section per finding (meaning, action, value vs limit, location, rule source, reviewer note, map picture) is written next to the HTML. HTML reports: enterprise-style neutral design (Inter, accessible WCAG AA colours, dark mode), KPI tiles, deep links (#F-0001), keyboard shortcuts (j/k/x/g/o/?), per-finding "checked" status saved in the browser with a review CSV, enlargeable map pictures, Word download button. QC Navigator: "Copy picture" (paste straight into Word) and "Word report" for the findings currently shown, rendered from the live QGIS map. Mid-span cable height: pole embedment 1/6 of pole length (national distribution construction standard), design sag 1.5 percent, review band 4.7-5 m (NESC 232-1) summarised, notes only below 4.7 m; span and cable-height labels no longer run together (span above the line, height below, dashed); re-running tool 1 in the same QGIS session no longer fails to overwrite the finding layer. 55 automated tests.
  3.5.1 Evidence-based tolerances (pass / review / fail). Tool 1: homepasses only a few metres outside the hand-drawn cluster BOUNDARY are reported as INFO "at the edge" within a GPS tolerance (default 10 m, GPS.gov 4.9 m open sky; PLOS ONE 2019 7-13 m urban) instead of a mandatory fix, and every boundary/Funnel/pole-distance finding now records its distance and limit; Design Lite double-tagging adds review bands (HP 2-5 m, new pole 1.5-10 m); unused survey poles are WARNING. Allocation tool: link-budget verdict uses design losses (1:4 7.25, 1:8 10.38, connector 0.25 dB) with a 3 dB margin; worst-case maxima are reported as "thin budget" instead of failing twice. Tool 4: slack spacing is checked on new cables only (existing/colo cables ignored); a cable tail after the last FAT within the loop limit (100 m / 2 spans) is WARNING, and spans are counted as spans, not poles. Post-design tool: floating-FAT tolerance taken from the profile. QC-01 grouping no longer treats the design FDT itself (already listed in the latest existing-network file or in the code register) as a group used elsewhere. New profile parameters with sources; 54 automated tests.
